# bowlam.com — public landing page

This directory is the **public** artefact: the page served at bowlam.com. It is
separate from `web/` on purpose.

| | `web/` | `site/` |
|---|---|---|
| What it is | The research console | The public landing page |
| Who sees it | You, on this machine | Anyone |
| Corpus access | Live, over `/api/` | **None.** Counts are baked in at build time |
| Deployed | **Never** — binds to localhost and refuses non-local addresses | Cloudflare Pages |

Two rules shape everything here, and neither should be relitigated at build
time (`docs/project-rules.md` §3, ACCESS-008/009):

1. **The console is not the deliverable.** It must never be exposed. That is
   why the public page is a separate, generated, flat file rather than the
   console with its navigation hidden — a hidden link is still a link.
2. **The public page has no path to the corpus.** No `/api/` call, no route
   into the console, no per-object data. Only aggregates cross the boundary,
   and `tests/test_public_site.py` fails the build if that stops being true.

## Layout

```
site/
  src/            Hand-edited sources — edit these
    public.css      standalone; imports nothing from web/
    bowl.svg        artist's impression (not an artifact photograph)
    map.svg         schematic region (not a findspot distribution)
    _headers        CSP and cache headers
    robots.txt
  functions/
    api/interest.js Pages Function: POST /api/interest -> D1
  public/         GENERATED by the build — do not hand-edit
  schema.sql      D1 schema for the interest list
  wrangler.toml   Pages + D1 config
```

## Rebuild the page

Counts are a snapshot, not a live feed, so the page needs rebuilding whenever
the corpus moves enough to be worth republishing:

This one runs from the **repo root**, not from here — it needs the corpus:

```sh
cd ~/Developer/incantation-bowl-index
PYTHONPATH=src .venv/bin/python scripts/build_public_site.py
```

The script prints the snapshot digest it used and refuses to write a page
containing an identity id, a corpus endpoint or a console route.

## First-time Cloudflare setup

Every `wrangler` command below must run **from this directory**, not from the
repo root and not from your home directory. Wrangler reads `wrangler.toml` and
`schema.sql` relative to where it starts, so running it elsewhere fails with
`Unable to read SQL text file "schema.sql"` — or, worse, succeeds at creating
the database while silently leaving `database_id` unset here.

```sh
cd ~/Developer/incantation-bowl-index/site
```

Then, once:

```sh
npx wrangler d1 list                                        # already created?
npx wrangler d1 create bowlam-interest --update-config      # if not; writes the id below
npx wrangler d1 execute bowlam-interest --remote --file=schema.sql
```

`--update-config` is what fills in `database_id` in `wrangler.toml`. Without
it you have to paste the id by hand, and a forgotten paste shows up later as
a 503 from the signup form rather than an error at deploy time.

## Deploy

```sh
cd ~/Developer/incantation-bowl-index/site && npx wrangler pages deploy
```

Then point the `bowlam.com` custom domain at the Pages project in the
Cloudflare dashboard.

## Read and export the interest list

```sh
cd ~/Developer/incantation-bowl-index/site
npx wrangler d1 execute bowlam-interest --remote \
  --command "SELECT email, created_at FROM interest_active"
```

`interest_active` excludes anyone who has asked to be removed. To retire an
address, set `unsubscribed_at` rather than deleting the row — a deleted row
comes back the next time an old list is imported:

```sh
npx wrangler d1 execute bowlam-interest --remote \
  --command "UPDATE interest_signups SET unsubscribed_at = datetime('now') WHERE email = 'someone@example.org'"
```

## Before this goes live

- [ ] Confirm `database_id` in `wrangler.toml` is a real id, not the
      placeholder. `--update-config` sets it; running `d1 create` from any
      other directory does not.
- [ ] Apply `schema.sql` to the **remote** D1, not just the local one.
- [ ] Decide what the unsubscribe link in your first mailing will point at. The
      page promises one-click unsubscribe; the schema supports it, but nothing
      sends mail yet.
- [ ] Add a privacy notice covering the interest list, and link it from the
      form. The page tells people how their address will be used, which is the
      substance of it, but a public form collecting addresses from EU and UK
      visitors is generally expected to name a controller and a lawful basis.
      This is a decision for you and, if you want certainty, for counsel — it
      is not an agent's call.
- [ ] Re-read the page copy once as a stranger would. It is project-authored
      and cites its sources (`docs/homepage_sources.md`), but it is the first
      thing the field will see.

## Local development

```sh
cd ~/Developer/incantation-bowl-index/site
npx wrangler d1 execute bowlam-interest --local --file=schema.sql
npx wrangler pages dev
```

`site/.wrangler/` holds the local D1 and is gitignored: addresses typed into
the local form are real addresses.
